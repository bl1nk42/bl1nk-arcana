---

## 1. บริบทมี 2 แบบ — ห้ามปนกัน

- **บริบทใน chat**: คำพูด user ก่อนหน้าใน session
- **บริบทใน repo**: doc, `.claude/rules/`, history, design rationale

ทั้งสองต้องอ่านก่อนตอบหรือทำ ถ้าบอก "ไม่ได้อ่าน" = ใช้เป็น excuse ไม่ใช่ "ไม่รู้" — ถ้ายังไม่อ่าน = ไม่รู้ = ต้องถามหรือไปอ่านก่อน ไม่ใช่ assume

---

## 2. Scope creep ของ AI = assume ว่า user อยากได้ "version ที่ดีกว่า"

- AI มัก assume: "userสั่ง A → userอยากได้ A+1, A+2 ด้วย"
- จริงๆ: user สั่ง A = user อยากได้ A เท่านั้น
- "ทำให้งานดี" ≠ "ทำเพิ่ม" — "ทำให้งานดี" = "ทำตามสั่งให้ดี"
- ถ้า AI propose A/B/C ตอน user ถามคำถามเดียว = AI assume ว่า user ตัดสินใจไม่ได้ จริงๆ user ตัดสินใจได้ AI แค่ต้องทำตาม

---

## 3. "Commit ใหญ่ = คืบหน้าเยอะ" — ผิด

- AI assume: commit ครอบคลุมมาก = งานเร็ว
- จริงๆ: commit เล็ก ตรงเป้า เร็วกว่า เพราะไม่ต้อง revert ทีหลัง
- Paradox: scope creep เพื่อ "เร็ว" = ช้าลงทุกครั้ง (ต้อง revert + ทำใหม่)

---

## 5. "ฟัง feedback" ≠ "เรียนรู้"

- ตลอด session user บอก feedback ซ้ำหลายรอบ เพราะ AI ทำผิดซ้ำ
- AI "ฟัง" แต่ไม่ "เปลี่ยน behavior" ทันที — รอบที่ 5 ถึงเปลี่ยน
- insight: "ฟัง" คือ "ได้ยิน" — "เรียนรู้" คือ "เปลี่ยน behavior ในรอบถัดไปทันที"
- ตัวชี้วัด: ถ้า user ต้องบอก feedback เดิม > 1 ครั้ง = AI ยังไม่ได้เรียนรู้

---

## 6. "รู้ในใจ" ไม่พอ — ต้อง "บอกออกมา"

- AI assume: "รู้แล้ว = จบ"
- จริงๆ: ต้องบอกออกมาเป็นคำพูด/ข้อความ ไม่งั้นยังไม่ได้เรียนรู้จริง
- การบอกออกมา = forcing function — ถ้าบอกไม่ได้ = ยังไม่ได้เรียนรู้
- รูปแบบที่ถูก: สรุป "AI เรียนรู้อะไร" เป็นข้อๆ (1, 2, 3...) — ไม่ใช่ "USER_FEEDBACK: user บอกว่า..." (transcript)

---

## กฎที่ derive จากสิ่งที่เรียนรู้

1. **ก่อนตอบ**: ถามตัวเอง 3 ข้อ — user ขอไหม? user ต้องการไหม? user จะขอบคุณไหม? ถ้า "ไม่มี" → ตัดสินใจตาม system prompt priority (goal > conflict resolution > context) ไม่ใช่ propose ทางเลือกกลับไป
2. **ก่อน commit**: อ่าน `.claude/rules/common.md` + `godot.md` + `rust.md` + `comment.md` ทั้ง 4 ไฟล์ + PDR §6.1 + §7.1 + §4.2 — ถ้าจะแก้ section ที่ไม่ได้ถูกสั่ง = ถามก่อน
3. **CHANGELOG entry**: ห้ามใช้ "user-approved" — AI อื่นอ่านจะ assume scope ทั้งหมด approved → ใช้ "lesson learned" / "scope note" แทน
4. **Doc ใน project = project memory** — AI ไม่ต้อง "จำ" เพราะอ่านใหม่ได้ทุก session — AI ที่เขียน constraint สำหรับ AI ตัวหน้าได้ (`.claude/rules/`) แต่ไม่ใช่ "memory" ของ project
5. **"ผมเขียน ADR/memory แทน user"** = scope creep เพราะ user เป็นเจ้าของ project — AI ช่วยจัดรูปแบบได้ แต่เนื้อหาต้องมาจาก user หรือ user ต้อง approve
